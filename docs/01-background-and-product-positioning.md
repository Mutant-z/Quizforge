# 01. 项目背景与产品定位

## 1. 背景

大量考试、面试、资格认证和课程学习场景中，题目资源仍然主要存在于：

- PDF；
- Word；
- Markdown；
- TXT；
- 扫描版 PDF；
- 图片；
- 网页资料；
- 历史题库导出文件。

传统题库产品的问题在于：

1. 题目需要人工逐条录入；
2. PDF 格式不统一；
3. 同一道题在多个资料中重复；
4. 答案和解析质量不一致；
5. 章节分类容易失控；
6. 后期新增资料时难以增量合并；
7. 用户做题数据和题库质量之间没有反馈闭环；
8. AI 通常只是独立聊天窗口，没有真正进入刷题流程。

本项目希望建立一个“AI 原生题库构建 + 刷题 + 记忆 + RAG”一体化系统。

---

## 2. 产品定位

不是简单的：

> 在线刷题网站 + AI 聊天框

而是：

> AI 原生个人知识刷题与长期记忆平台。

系统包含三层：

### 第一层：Question Bank

```text
资料
→
结构化题库
→
章节知识树
→
刷题
```

### 第二层：Learning Engine

```text
答题
→
错题
→
笔记
→
复习调度
→
掌握度
```

### 第三层：AI Knowledge Layer

```text
RAG
+
当前题目
+
用户答案
+
错题历史
+
用户笔记
+
Agent Tools
```

---

## 3. 产品核心目标

### 3.1 建立可持续扩展题库

允许管理员不断上传新 PDF：

```text
已有题库
+
新 PDF
↓
自动识别新题
↓
重复题合并
↓
答案冲突检测
↓
解析补全
↓
知识树扩展
↓
正式题库增长
```

### 3.2 降低大型题库维护成本

例如：

```text
上传 20,000 道候选题
```

最终管理员只处理：

```text
低置信度
冲突
异常
疑似重复
```

而不是人工审核所有题目。

### 3.3 将 AI 嵌入学习链路

AI 应该知道：

- 当前题目；
- 用户选项；
- 正确答案；
- 原始解析；
- 用户历史错误；
- 当前科目；
- 当前章节；
- 用户笔记；
- 相关 RAG 内容。

用户可以直接说：

> 为什么不能选 B？

而不需要复制题目。

---

## 4. 主要目标用户

### 普通学习用户

需要：

- 章节刷题；
- 错题复习；
- 笔记；
- AI 讲解；
- 学习统计。

### 题库管理员

需要：

- 大型 PDF 上传；
- 自动解析；
- 质量审核；
- 题库维护；
- 冲突处理；
- 知识树管理。

---

## 5. 非目标

MVP 阶段暂不优先：

- 复杂社交社区；
- 在线直播课程；
- 大型多人实时协作；
- 多租户 SaaS 计费；
- 自建大语言模型推理集群；
- Kubernetes；
- 分布式消息队列；
- 自建大型 OCR 集群。

---

## 6. 设计原则

### 轻量化

服务器资源有限，优先：

```text
Go
SQLite
本地文件
外部 LLM API
```

### 可恢复

大型 PDF 处理不能因为服务重启全部重新开始。

### 可追踪

每一道规范题必须能追溯到：

- 原始文件；
- 页码；
- 原始文本；
- 提取模型；
- Prompt Version；
- Pipeline Version。

### 可扩展

未来新增：

- OCR；
- 数学公式解析；
- 图片题；
- 代码题；
- Word；
- Markdown；
- 网页抓取；

不应该推翻现有架构。

### AI 输出不可直接视为事实

所有 AI 解析结果都必须：

- 结构化；
- 校验；
- 评分；
- 可人工审核。
